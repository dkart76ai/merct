## Field Schema (Player Flags)

Opcode 24301 retrieves flag/capture point status for a player. Each flag has a level and timestamp.

### Request

| Index | Type | Field Name | Description |
|-------|------|------------|-------------|
| 0 | `Array` | `objectId` | Single-element array with player map object ID |

Example: `[[1215523913815]]`

### Response

| Index | Type | Field Name | Description |
|-------|------|------------|-------------|
| 0 | `Array` | `header` | `[24301, sequence]` |
| 1 | `Array` | `flagsData` | Array containing flag status object(s) |

### Flags Data Structure

The server decoder (`scanPacket24301`) shows the response is a map of objectId to flag data:

```json
{
  "1198295910531": [19, 1777835062],
  "1198295933781": [19, 1777835062],
  "1198295959826": [30, 1777835062]
}
```

Each entry:
- **Key**: Object ID (string) of the flag/capture point
- **Value[0]**: Flag level (e.g., 19, 30, 35)
- **Value[1]**: Timestamp (Unix seconds) of last capture/update

### Notes

- The response `[1]` element is `[{}]` when no flags exist.
- Flag levels observed: 19, 30, 35 (possibly different tiers of capture points).
- Timestamps are the same within a single response, suggesting batch updates.


## ID Tracking

References IDs identified from opcode 402 analysis:
- **objectId**: map object ID (large int64, changes on relogin)
- **playerId**: persistent player ID (format `tb:{N}`
- **clanId**: clan identifier (in single-element array, `[0]` = no clan)
