## Field Schema (Change Kingdom Response)

Opcode 313 is triggered when the player switches kingdoms. The response contains full player state for the new kingdom.

### Request

Empty request `[]` -- server determines target kingdom from URL/session.

### Response Structure

The response has 3 top-level elements:

| Index | Type | Field | Description | Example |
|-------|------|-------|-------------|---------|
| 0 | `Array` | `header` | `[313, sequence]` | `[313, 1431]` |
| 1 | `Array` | `payload` | `[playerState, tokenBuffer, 0]` | See below |
| 2 | `Number` | trailing | Always `0` | `0` |

### Payload (response[1])

| Index | Type | Field | Description |

### Timers (response[1][0][18])

When non-empty, entries like `[50100, 0, startTime, endTime]`:
- Index 0: Timer type ID (50100-50103 seen)
- Index 1: Always `0`
- Index 2: Start timestamp (Unix seconds)
- Index 3: End timestamp (Unix seconds)
- Gap is consistently 86400 seconds (24 hours)


## ID Tracking

References IDs identified from opcode 402 analysis:
- **objectId**: map object ID (large int64, changes on relogin)
- **playerId**: persistent player ID (format `tb:{N}`
- **clanId**: clan identifier (in single-element array, `[0]` = no clan)
